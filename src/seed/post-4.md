本站的文章、TIL、关于页都用 Markdown 编写。这篇整理了日常写作最常用的语法，以及本站额外支持的提示块。写文章时忘了某个写法，回来查这一篇就行。

> [!TIP]
> 后台编辑器的工具栏已经内置了大部分语法，点按钮就能插入；截图可以直接 `⌘V` 粘贴，会自动压缩、上传并插入图片语法。

## 标题

~~~markdown
## 二级标题
### 三级标题
#### 四级标题
~~~

> [!NOTE]
> 文章标题本身就是一级标题，**正文从 `##` 开始**，按层级往下用，不要跳级。正文里的二级、三级标题会自动生成右侧目录；标题少于 3 个时不显示目录。

## 强调

| 写法 | 效果 |
| --- | --- |
| `**粗体**` | **粗体** |
| `*斜体*` | *斜体* |
| `***粗斜体***` | ***粗斜体*** |
| `~~删除线~~` | ~~删除线~~ |
| `` `行内代码` `` | `行内代码` |

> [!WARNING]
> 中文写作最常见的坑：**结束的 `**` 前面紧挨着标点、后面紧跟文字时，粗体不会生效**。例如 `**注意：**这里` 会原样显示星号。把标点移到星号外面就好：`**注意**：这里`。

## 代码块

用三个反引号包住代码，并在开头写上语言名，就会有语法高亮：

~~~~markdown
```sql
SELECT user_id, COUNT(*) AS order_cnt
FROM dwd_trade_order_di
WHERE dt = '2026-10-22'
GROUP BY user_id;
```
~~~~

效果：

```sql
SELECT user_id, COUNT(*) AS order_cnt
FROM dwd_trade_order_di
WHERE dt = '2026-10-22'
GROUP BY user_id;
```

常用的语言名：

| 语言 | 写法 |
| --- | --- |
| SQL | `sql` |
| Python | `python` |
| Java / Scala | `java` / `scala` |
| Shell 命令 | `bash` / `shell` |
| 配置文件 | `yaml` / `json` / `properties` / `ini` / `xml` |
| 代码对比 | `diff` |
| 不需要高亮 | `text` |

`diff` 适合展示改动前后的对比：

```diff
- SELECT * FROM orders WHERE substr(dt, 1, 7) = '2026-10'
+ SELECT * FROM orders WHERE dt >= '2026-10-01' AND dt <= '2026-10-31'
```

> [!TIP]
> 代码块右上角会自动显示语言名和「复制」按钮。如果代码内容本身包含三个反引号，外层可以改用 `~~~` 包裹。

## 表格

~~~markdown
| 层级 | 职责 | 示例表 |
| :--- | :---: | ---: |
| ODS | 贴源 | ods_trade_order_di |
| DWD | 明细 | dwd_trade_order_di |
| DWS | 汇总 | dws_trade_user_1d |
~~~

效果：

| 层级 | 职责 | 示例表 |
| :--- | :---: | ---: |
| ODS | 贴源 | ods_trade_order_di |
| DWD | 明细 | dwd_trade_order_di |
| DWS | 汇总 | dws_trade_user_1d |

- 第二行的分隔线是必须的，用来区分表头和内容
- `:---` 左对齐，`:---:` 居中，`---:` 右对齐
- 单元格里要写竖线时，用 `\|` 转义
- 列比较多的表格，在手机上可以左右滑动查看
- 表格前后各空一行，否则可能和上下文粘在一起

> `---` 的上方一定要空一行。如果紧贴着上一行文字，那行文字会被当成二级标题。

## 提示块（本站扩展）

标准 Markdown 没有提示块，这是本站额外支持的语法，写法和 GitHub 一致：

~~~markdown
> [!TIP]
> 技巧：一些好用的做法。

> [!NOTE]
> 说明：补充背景信息。

> [!WARNING]
> 注意：容易出错的地方。

> [!DANGER]
> 危险：可能造成数据丢失的操作。
~~~

效果：

> [!TIP]
> 技巧：一些好用的做法。

> [!NOTE]
> 说明：补充背景信息。

> [!WARNING]
> 注意：容易出错的地方。

> [!DANGER]
> 危险：可能造成数据丢失的操作。

`[!TIP]` 必须写在引用块的第一行，大小写都可以。两个提示块之间要空一行，否则会合并成一个。

## 脚注

~~~markdown
Spark 3.0 引入了自适应查询执行[^aqe]。

[^aqe]: Adaptive Query Execution，运行时根据统计信息调整执行计划。
~~~

效果：

Spark 3.0 引入了自适应查询执行[^aqe]。

[^aqe]: Adaptive Query Execution，运行时根据统计信息调整执行计划。

脚注的内容会统一显示在文章末尾，点击编号可以来回跳转。脚注定义可以写在文章任意位置。

## 转义

想显示 Markdown 符号本身，而不是让它变成格式，在符号前面加反斜杠：

~~~markdown
\*这不是斜体\*

\# 这不是标题

1\. 这不是有序列表
~~~

效果：

\*这不是斜体\*

\# 这不是标题

1\. 这不是有序列表

可以用反斜杠转义的符号包括：反斜杠、反引号、星号、下划线、花括号、方括号、圆括号、井号、加号、减号、点、感叹号、竖线。

## 本站暂不支持的写法

| 写法 | 说明 |
| --- | --- |
| HTML 标签，如 `<br>`、`<span>` | 出于安全考虑会被过滤掉，请用 Markdown 语法代替 |
| 数学公式 `$...$` | 暂不支持，会按原文显示 |
| Mermaid 流程图 | 暂不支持，只会显示成普通代码；可以用 `text` 代码块画字符图，或者直接贴截图 |
| 图片尺寸、居中 | 暂不支持，图片默认按正文宽度显示 |

## 写作习惯建议

1. 正文从 `##` 开始，标题层级不要跳
2. 中文和英文、中文和数字之间加一个空格，例如「用 Spark 3 跑任务」
3. 代码块一定写上语言名
4. 表格、提示块、代码块的前后都空一行
5. 一段只讲一件事，长段落拆成几段
